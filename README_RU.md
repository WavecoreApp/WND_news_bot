# WND | Main Digest — бот новостного дайджеста

Бот раз в час (в 17 минут каждого часа) собирает свежие мировые новости, оценивает их,
переписывает сильные истории на русском и публикует в канал https://t.me/wnd_digest.
Работает бесплатно: GitHub Actions + бесплатный тариф Gemini.

## Как это работает

1. **Сбор.** Бот читает RSS из `sources.txt`: Reuters и AP (через Google News и Flipboard),
   WSJ, BBC, DW, France 24, Al Jazeera. Берутся только новости за последние 24 часа.
   Спорт, знаменитости, реклама и азартные игры отсекаются сразу.
2. **Оценка.** Gemini ставит каждой новости три оценки от 1 до 10: важность, новизна и охват.
   Итог = 0,5 × важность + 0,2 × новизна + 0,3 × охват. Публикуется только то, что набрало
   `MIN_SCORE_TO_POST` (по умолчанию 7) и выше.
3. **Защита от повторов.** Одно и то же событие не публикуется дважды: бот сравнивает ссылки,
   заголовки и «ключ события» с тем, что уже выходило за последние 72 часа, а затем
   один раз за запуск просит Gemini проверить, не про одно ли событие новости. Если событие
   есть у нескольких изданий, берётся лучшее по приоритету: Reuters, AP, BBC, DW, WSJ,
   France 24, Al Jazeera.
4. **Текст.** Для каждой отобранной новости бот скачивает статью и пишет короткий пост
   (2–4 предложения, ключевые факты **жирным**). Новость, по которой нет ни текста статьи,
   ни нормального описания, пропускается.
5. **Публикация.** Пост выходит с картинкой из самой статьи (или с прямым видео) и двумя
   кнопками: «📰 Оригинал» и «✨ WND Digest». Между постами случайная пауза 30–120 секунд.
   Дневного лимита нет: много сильных новостей — много постов. За один запуск выходит не больше
   `MAX_POSTS_PER_RUN` постов, остальные ждут в очереди и выходят первыми в следующий час.
6. **Память.** Всё, что бот уже видел и опубликовал, хранится в небольшом файле `state.json`.
   После каждого запуска бот сам сохраняет его в репозиторий.

## Секреты (обязательно)

Откройте репозиторий на GitHub → **Settings** → слева **Secrets and variables** → **Actions** →
вкладка **Secrets** → кнопка **New repository secret**. Введите имя (Name) и значение (Secret),
нажмите **Add secret**. Чтобы изменить существующий секрет, нажмите на карандаш рядом с ним.

| Имя | Что это |
|---|---|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather. Бот должен быть администратором канала. |
| `GEMINI_API_KEYS` | Один или несколько ключей Gemini через запятую, без пробелов: `ключ1,ключ2`. |
| `GROQ_API_KEY` | Необязательно. Запасной вариант, если ни одна модель Gemini не смогла написать текст. |
| `JINA_API_KEY` | Необязательно. Ключ сервиса чтения статей r.jina.ai (см. ниже). Без него бот тоже работает. |

**Важно про ключи Gemini.** Бесплатные лимиты Google считаются на **проект** Google Cloud,
а не на ключ. Несколько ключей из одного проекта ничего не дают. Чтобы ключи помогали, каждый
должен быть из **отдельного проекта**: на https://aistudio.google.com/apikey нажмите
**Create API key** → **Create API key in new project** и повторите для каждого ключа.

## Переменные

Там же: **Settings** → **Secrets and variables** → **Actions** → вкладка **Variables** →
**New repository variable**.

| Имя | По умолчанию | Что это |
|---|---|---|
| `TELEGRAM_CHANNEL_ID` | — (обязательно) | Канал, например `@wnd_digest`. |
| `DIGEST_CHANNEL_URL` | `https://t.me/wnd_digest` | Ссылка для кнопки «✨ WND Digest». |
| `MIN_SCORE_TO_POST` | `7` | Порог публикации (от 1 до 10, можно дробное: `7.5`). |

Остальные настройки задаются прямо в файле `.github/workflows/main.yml` (блок `env:`
шага «Run news bot»), а **не** в переменных репозитория. Чтобы изменить: откройте файл на GitHub,
нажмите карандаш (**Edit this file**), поменяйте число и нажмите **Commit changes**.

| Имя | По умолчанию | Что это |
|---|---|---|
| `MAX_POSTS_PER_RUN` | `12` | Сколько постов максимум за один запуск (остальные — в очередь). |
| `POST_DELAY_MIN_SECONDS` | `30` | Минимальная пауза между постами, секунд. |
| `POST_DELAY_MAX_SECONDS` | `120` | Максимальная пауза между постами, секунд. |
| `MAX_POSTS_PER_DOMAIN` | `6` | Сколько постов максимум из одного издания за запуск. |
| `ENTRIES_PER_SOURCE` | `25` | Сколько последних записей читать из каждой RSS-ленты. |
| `GEMINI_SCORE_MODELS` | `gemini-3.1-flash-lite,gemini-3.5-flash-lite,gemini-3.6-flash` | Модели для оценки и проверки повторов, по порядку: если первая не отвечает, берётся следующая. |
| `GEMINI_REWRITE_MODELS` | `gemini-3.6-flash,gemini-3.1-flash-lite,gemini-3.8-flash` | Модели для текста поста, тоже по порядку (самая новая и часто перегруженная — последней). |
| `GROQ_FALLBACK_MODEL` | `openai/gpt-oss-120b` | Запасная модель Groq для текста (только если задан `GROQ_API_KEY` и все модели Gemini не сработали). |

## Запуск вручную

**Actions** → слева **WND Digest Bot** → справа **Run workflow** → зелёная кнопка **Run workflow**.
Через несколько секунд появится запуск; нажмите на него, затем на **run-news-bot**, чтобы
увидеть журнал. Строки `SUMMARY` показывают итог каждого этапа: сколько собрано, оценено,
прошло порог, осталось после проверки повторов, опубликовано, отложено в очередь.

## Если что-то не работает

**В журнале «503 UNAVAILABLE» или «high demand».** Это временная перегрузка у Google, а не
ошибка бота и не проблема ваших ключей. Бот один раз ждёт около 5 секунд и, если модель так и не
отвечает, сразу переключается на следующую модель из списка (дольше — 5, 15 и 40 секунд — он ждёт,
только если это последняя оставшаяся модель). Не ответившую модель он на 10 минут откладывает. Ничего делать не нужно. Если перегрузка сильная, часть новостей останется
неоценённой; их бот попробует снова в следующий час.

**В журнале «MODEL NOT FOUND» или ошибка 404 с именем модели.** Значит, Google переименовал
или убрал эту модель. Бот на время запуска пропускает её и берёт следующую, но имя нужно
поправить. Откройте на GitHub файл `.github/workflows/main.yml` → карандаш (**Edit this file**) →
найдите строки `GEMINI_SCORE_MODELS:` и `GEMINI_REWRITE_MODELS:` (в блоке `env:` шага
«Run news bot») → замените имя модели из ошибки на актуальное (список бесплатных моделей —
на https://ai.google.dev/gemini-api/docs/models) → **Commit changes**. Используйте только
модели Flash и Flash-Lite: модели Pro на бесплатном тарифе недоступны.

**Зачем нужен `JINA_API_KEY`.** Некоторые сайты (например, AP или WSJ) не отдают статью боту.
Тогда бот читает её через бесплатный сервис r.jina.ai; без ключа это не больше 10 статей за запуск.
Если в журнале часто видно «Reader fallback rate limited», можно бесплатно получить ключ на
https://jina.ai и добавить его как секрет `JINA_API_KEY` (так же, как остальные секреты).
Если текст всё равно не получить, очень сильные новости (оценка 8 и выше) выходят короткой
«молнией» в 1–2 предложения только по заголовку и описанию, остальные пропускаются.

## Если бот замолчал

GitHub отключает расписание в публичных репозиториях, если в них 60 дней не было активности.
Обычно этого не происходит, потому что бот каждый час сохраняет `state.json`. Но если постов нет:

1. Откройте вкладку **Actions**.
2. Если сверху жёлтая плашка о том, что workflow отключён, нажмите слева **WND Digest Bot**,
   затем кнопку **Enable workflow**.
3. Если плашки нет, откройте последний запуск и посмотрите, на каком шаге красный крестик.
   Частые причины: не задан секрет, закончился бесплатный лимит Gemini, бот не админ канала.

## Файлы

- `bot.py` — код бота.
- `sources.txt` — список RSS-лент (одна ссылка на строку, `#` — комментарий).
- `state.json` — память бота (создаётся автоматически, руками не править).
- `requirements.txt` — библиотеки Python.
- `.github/workflows/main.yml` — расписание и настройки.
- `urls_base.txt` — старая база, больше не используется; её можно удалить
  (откройте файл на GitHub → меню «…» → **Delete file** → **Commit changes**).
